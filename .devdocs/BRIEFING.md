- **Phase:** Phase 57 (**ROOT CAUSE FOUND AND FIXED — awaiting user build**). The window-close crash is a wlroots-side assertion, not a hikari memory bug. `src/xdg_view.c` registered `request_fullscreen` on the **xdg_toplevel** but removed it in `destroy_handler`, which is bound to the **xdg_surface**. wlroots 0.20 destroys the toplevel role object *before* emitting the xdg_surface destroy signal, and `destroy_xdg_toplevel()` asserts every toplevel signal has no listeners left — so wlroots `abort()`ed (SIGABRT) on every window close, three lines before hikari's cleanup ran. Fixed by adding a `toplevel_destroy` listener on `xdg_toplevel->events.destroy` that releases the toplevel-scoped listener (and itself) at the right moment. **Two corrections to earlier phases:** (1) Phase 53 concluded the binary was a `DEBUG=YES` build with hikari assertions live — wrong; it is a release `-DNDEBUG` build with hikari's assertions compiled out, and the aborting assertion was inside `libwlroots-0.20.so`, which *is* built with assertions on. - **Phase 55** (Root-Cause Architecture Analysis + Single-Writer Visibility Refactor) — analysis and plan; superseded by Phase 56's execution. Answers the question "is the architecture itself causing the crashes": **yes, and the flaw is nameable** — the fact *"this view is visible"* is stored in **six** independent representations (hidden flag, `workspace->views`, `hikari_server.visible_views`, `group->visible_views`, the `group->visible_server_groups` aggregate, and the scene-node enabled bit) with **no single writer**. Entry is split across two functions callers must remember to pair; exit is one function; `hikari_view_lower()` hand-writes the whole linkage a third time. Group lifetime then depends on an unwritten, unasserted invariant linking two of those representations — and `hikari_view_unmap()` contains a branch that sets the hidden *flag* without performing the *transition*, then frees the group, producing a simultaneous three-list + freed-group use-after-free. That is exactly the delayed-corruption signature behind the long history of "random" crashes and the current SIGABRT-with-no-core. Remediation is a bounded refactor — **Single-Writer Visibility Transitions** — confined mostly to `src/view.c`, ~18 call sites, fully wired function-by-function in `PLANS.md` item -6. Explicitly **not** the Phase 44 DOD/SoA rewrite (that rejection stands; allocation strategy is unchanged). Honest caveat: this removes a defect *class* plus one specific identified UAF path, but has not been proven to be the exact live crash, because no crash output or core has been captured yet — Step 4 (headless smoke test under `MALLOC_CONF=junk:true`) closes that gap and should be built first.
